Project boards

CodeCoverage keeps your GitHub Projects boards up to date. When an issue or pull request changes, it moves the card to the column you chose for that event, so nobody has to drag cards by hand.

You write the rules per board: when a pull request is merged, move it to Done. A rule applies to the issues and pull requests of every repository of the account that owns the board.

Install the CodeCoverage GitHub App on the organization that owns the board; Home links it once you are signed in. Moving cards needs these App permissions:

  • Organization projects: read and write, to read the board and move its cards.
  • Issues and Pull requests, to know which issues a pull request closes.
  • Checks, for rules on Check run completed.

The App listens to the Issues, Pull request, Pull request review, Issue comment and Check run events.

Only boards owned by an organization can be automated. GitHub gives Apps no access to a board owned by a personal account, so such a board never appears in CodeCoverage. Move the board to an organization, or create it there. When the App asks for a new permission, an owner of the organization has to accept it on GitHub, under the organization's installed GitHub Apps. Until then GitHub sends no events for it, and nothing moves. } @case ('board') {

The columns are the options of the board's Status field: the single-select field GitHub Projects creates with every board, which its board layout shows as columns. Keep it named Status (in any case). A board without it has no columns to move cards between.

Create the columns you want, such as Todo, In progress, In review and Done, before you write rules: a rule can only point at a column that already exists.

} @case ('find') {

Open the account's page and its Project boards tab. It lists the boards the App can see. Nobody adds a board by hand: CodeCoverage finds the boards itself, up to 100 per account, every night.

A board you just created shows up after the next nightly run, or sooner with Resync on Home. You see the boards of every account you can see, and you edit those of the accounts you manage. A board the App can no longer reach drops off the list.

} @case ('enable') {

Open the board and choose Edit:

  1. Switch on Automation Enabled and save. Switched off, the board is listed but no event does anything.
  2. Choose Sync columns. It reads the Status field's options from GitHub; Columns then lists them, and Columns Synced says when.

The columns are also read again every night.

} @case ('rules') {

The rules are the board's Events list. Add a row for each event that should move a card. A rule has these fields:

A common set for a board with Todo, In progress, In review and Done:

  • Issue opened → Todo
  • Pull request opened → In progress, with Move Linked Issues
  • PR ready for review → In review
  • PR converted to draft → In progress
  • Pull request merged → Done, with Move Linked Issues
  • Issue closed → Done
  • Issue reopened → Todo
} @case ('events') {

The Event dropdown offers these, grouped by what they move:

  • The issues a pull request closes are the ones GitHub links to it: those named with a closing keyword in its description, such as Closes #12, or linked under Development in its sidebar. They move only when the rule has Move Linked Issues.
  • Pull request merged and Pull request closed without merging are told apart, and so are an approving review and one that requests changes, so each can go to its own column.
  • Check run completed fires for every check, red or green. GitHub does not link a check run to a pull request from a fork, so those cards do not move on it.
  • The check runs and comments CodeCoverage writes itself never trigger a rule, so posting its own coverage feedback does not move a card.
} @case ('columns') {

GitHub sends no event when you rename, add or delete a column. CodeCoverage notices at the next nightly run; choose Sync columns on the board to pick it up at once.

A rule whose column was deleted stops moving cards and records the error, and Sync columns names the rules it affects. Point them at another column, or delete them.

} @case ('troubleshoot') {

Each rule records how it last went:

  • Last Fired: when it last ran without an error.
  • Error and Failed At: why and when it last failed. They clear when it next succeeds.

If a card does not move and the rule shows nothing:

  • Is Automation Enabled on for the board, and Enabled on for the rule?
  • Has an organization owner accepted the App's permissions? GitHub sends nothing until they have.
  • Is the issue or pull request on the board? With Add To Board off, a card that is not on it is skipped.
  • Is the board still listed? A board the App can no longer reach, deleted or with the App's access removed, drops off the account's list.
  • Does the rule point at a column that still exists? Choose Sync columns after changing the columns.
  • Is the board owned by an organization? A board owned by a personal account is out of the App's reach.
} } }
