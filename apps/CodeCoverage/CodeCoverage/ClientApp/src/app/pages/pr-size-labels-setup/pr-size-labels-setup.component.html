PR size labels

CodeCoverage labels every pull request with its size, size/XS to size/XXL, from the lines it changes. Reviewers see at a glance what they are taking on, and authors see when a pull request should be split.

The size is the sum of the lines added and deleted in every file that counts. It is computed again on every push, and a pull request carries exactly one size label at a time. Your own labels are never touched.

The Size scale is on the account, one row per label: a pull request that changes at least a row's number of lines, and fewer than the next row's, gets that row's label. A new account starts with:

LabelFrom linesColour @for (row of scale; track row.name) { {{ row.name }} {{ row.minLines }} {{ row.color }} }

The labels are the app's own: it creates them in each repository, and keeps them in step with the scale.

  • Renaming a row renames the label on GitHub, so every pull request that carries it, closed ones too, keeps it under its new name.
  • A new colour or description is written to the existing label.
  • Deleting a row deletes its label, and GitHub removes it from every pull request that carries it, closed ones included.
  • A label you archive on GitHub is left archived. Pull requests of that size then get no label, and the check says why.
} @case ('ignore') {

Generated files and lockfiles say little about how much there is to review, so some files count less. Ignored files on the account are rules of a glob and a mode:

  • Ignore: the file does not count at all.
  • Ignore additions: only the file's net deletions count, so a large generated file adds nothing while a large deletion still shows.

A new account starts with these, in this order:

GlobMode @for (rule of ignoreRules; track rule.glob) { {{ rule.glob }}{{ rule.mode }} }

The last matching rule wins. That is why **/package-lock.json comes after **/*.json: it is ignored outright rather than for its additions only. A glob that starts with ! counts the matching files fully again.

A repository adds its own Extra ignored files, which apply after the account's. They can ignore more, or count what the account ignores: !apps/web/**/*.json counts the JSON files under apps/web in full. A rule added to the account later applies to every repository that does not counter it.

Every labelled push gets a PR size check run. It is titled with the label and the size, such as size/M · 87 lines changed, and its summary lists the files that counted, the ignored ones and those counted for their deletions only, each with the rule that matched.

The check always completes neutral, even when the label could not be applied; it then says why. It never fails a pull request, so it never blocks a merge or the merge queue. } @case ('disable') {

Switching the labeller off, on the account or on a repository, asks what to do with the labels:

  • Remove labels deletes the app's labels from the repositories that stop labelling. Pull requests that carry them, closed ones included, lose them.
  • Keep labels stops labelling and leaves the labels where they are. Switching it on again picks them up.
  • Cancel saves nothing.
