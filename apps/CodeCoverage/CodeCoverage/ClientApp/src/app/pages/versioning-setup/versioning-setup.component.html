Package versioning

CodeCoverage versions your NuGet and npm packages for you. Nobody edits a version number: every release is a git tag <PackageId>/v<version>, such as Acme.Mapper/v13.2.0, and the tag is the only record of the version.

Your publish workflow runs one step after its tests. That step tags every package that changed, and the pack then reads the tags.

 @switch (step.id) { @case ('how') {
  • Only what changed is released. A package is released when a file it is built from changed since its last tag. A .NET package whose in-repository dependency is released is released too.
  • The major follows the platform. It comes from the highest netX target framework, or from the resolved @angular/core, react or vue. netstandard, net4x and plain node libraries keep the major of their last tag; you raise it by pushing a tag yourself.
  • Minor or patch comes from the public API. If the API changed, it is a minor; otherwise a patch. A breaking change is a minor too, because the major belongs to the platform.
  • Prereleases mirror upstream. When the platform or a dependency is a prerelease, the package gets the same label with its own counter, such as 11.0.0-rc.3.

Open the repository's page (from its account, in your GitHub accounts), run Set up features and tick Package versioning. It opens one pull request (how onboarding works) that:

  • adds MintPlayer.Versioning.MSBuild to Directory.Build.props;
  • replaces hand-edited versions with 0.0.0-PLACEHOLDER;
  • adds the versioning step and its permissions to your publish workflow, and fetch-depth: 0 to its checkouts;
  • adds a versioning: section to coverage.yml.

Review and merge it. At the merge CodeCoverage tags the history: every version your packages declared gets a tag at its earliest commit, so no package restarts at 0.0.0. Running Set up features again tags whatever is still missing.
