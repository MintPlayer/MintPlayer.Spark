Getting started

Pick the features you want for a repository, and CodeCoverage opens one pull request that sets them all up. Review it, merge it, and the app switches the rest on.

The pull request is planned from your default branch as it is. The bot keeps it up to date while it is open, so it never goes stale or conflicts with what merges in the meantime.

When you merge the pull request, the app:

  1. pushes one seed tag per package at the merge commit, when package versioning was picked;
  2. switches on dependency updates and PR size labels, when they were picked;
  3. renames the old line branches to release/<ecosystem>-<major>.x. GitHub moves their open pull requests along and redirects the old names;
  4. opens a pull request into each supported release line that lacks the default branch's regenerate workflow, from mintplayer/onboarding-<line>.

That last pull request copies the workflow as it is on the default branch. A backport into the line runs it on the line itself, so lockfiles and generated files are rebuilt with the line's own tools. Check it builds with the line's SDKs before you merge it.
