## 1. Why Polyglot, and for what

**The need.** The GS1 core has to run the same algorithm in two places, and both are tested against GS1's Syntax Engine vectors:
- `MintPlayer.Spark.Gs1`, a .NET 11 server library inside an ASP.NET Core host, under any culture;
- `@mintplayer/ng-spark/scanning`, an Angular secondary entry point.

That is Polyglot's stated sweet spot (Polyglot `docs/prd/POLYGLOT_PRD.md:27-30`: "validation rules on a .NET backend **and** an Angular frontend").

**Measured on Polyglot v0.10.1 (2026-10-17).** A probe ran the emitted C# under the invariant, en-US, nl-BE and tr-TR cultures (interpolation and parsing also under sv-SE, nb-NO and fa-IR) and the TS on Node 24.
- The **logic** is faithful in every culture: GTIN check digits 10/10, element-string parse 7/7, a pure code-point fold 16/16.
- It also found 6 correctness defects and 7 gaps that block library use. Those became #73.

**Scope (owner decisions, 2026-10-17, recorded in the #521 PRDs):**

| Use | Decision |
|---|---|
| GS1 core: element strings, Digital Link, AI linters, check digits | **Yes**, written once in `.pg`. This held only if a Polyglot release fixing #73 shipped before warehouse WM2. 0.10.2 did, so the hand-written fallback isn't needed. |
| GS1 tables (the AI dictionary) | Come from one `tools/` script, per Q-W16. Built: `tools/gs1/generate-ai-table.mjs` emits the vendored Syntax Dictionary as `.pg` data (`pg/aitable.pg`), and Polyglot turns that one table into the C# and the TS |
| Polyglot's C# surface | Stays **internal** behind a hand-written facade, and its types never cross the wire |
| CLI delivery | The `MintPlayer.Polyglot.MSBuild` NuGet restore. No global tool. |
| TS contracts (`ng-spark/<entry>/src/generated/contracts.ts`) | **Not** Polyglot. They come from Spark's C#→TS tool. |
| Money, Unicode folding, patterns, consumer tests, data embedding | **Later**, only when #74 ships (fixed-point money with rounding modes and allocation, consumer-exported cross-target `test` blocks, compile-time data embedding, a portable Unicode folding module, a portable pattern matcher). Until then money stays C# `decimal`, and folding and patterns stay platform-specific with fixtures. |

## 4. How Spark consumes Polyglot

**As built (PR #528):**
- **Project:** `libs/gs1/MintPlayer.Spark.Gs1/MintPlayer.Spark.Gs1.csproj` (package `MintPlayer.Spark.Gs1`), with `pg/*.pg` and `pgconfig.json` beside it. The generated C# is in namespace `MintPlayer.Spark.Gs1.Core`, class `Gs1Core`, `access: internal`, and the public facades are `Gs1CheckDigit`, `Gs1Barcode` and `Gs1Sscc`.
- **Twin:** routed with `owned: true` into `libs/node_packages/ng-spark/scanning/src/gs1/`. The barrel is `scanning/src/index.ts`, and the entry point is `@mintplayer/ng-spark/scanning`.
- **Package source:** `nuget.config` maps `MintPlayer.*` to `nuget.pkg.github.com/MintPlayer`, where releases appear minutes before nuget.org. Credentials come from `GH_PKG_USER`/`GH_PKG_TOKEN`; CI sets them to `github.actor` and `GITHUB_TOKEN` with `packages: read`.
- **Agreement with GS1:** `libs/gs1/corpus/gs1-corpus.json` holds 2,995 cases, with the Syntax Engine 1.4.1 WASM as the reference (`tools/gs1/build-corpus.mjs`). `tests/MintPlayer.Spark.Gs1.Tests` and `scanning/src/gs1-corpus.spec.ts` run it on both targets.

**Shape (as designed):**
- `libs/gs1/MintPlayer.Spark.Gs1.csproj` holds the `.pg` sources and a `pgconfig.json` beside the project. It references `MintPlayer.Polyglot.MSBuild` and sets `PolyglotTargets=csharp`, so the C# is generated into `obj/` on every build, with D17 cleanup.
- `targetOptions.csharp` gives the library its own `namespace` and `access: internal`. A hand-written public facade wraps it.
- The **TS twin** is committed and routed from the GS1 project's config into the ng-spark `scanning` entry point. The route leaves the config folder, like `../…/ng-spark/…/scanning/src/gs1/%(RecursiveDir)%(Filename)`.
- Developers refresh the twin with `polyglot build --only typescript`, run from the config dir. CI runs `polyglot build --check --only typescript` from the config dir (D3), with the packaged exe from the NuGet restore.

**Constraints learned in the review** (each one cost a repro):
1. **The owned twin folder holds Polyglot output only.** The barrel (`index.ts`) lives outside it. An owned scan deletes stale headed files, and no other generator's output may share the folder.
2. **No formatter on the twin.** The header must stay within the first 5 lines, and `--check` compares bytes.
3. **Pin `eol=lf` for the twin** in `.gitattributes`, again because `--check` compares bytes.
4. **Refresh with `polyglot build --only typescript`.** A bare `polyglot build` also writes `.cs` next to the `.pg`, which then collides with the MSBuild-generated copy (CS0111).
5. **Run the check from the config dir.**
6. **Top-level function names must be unique across modules.** There is no `private fn`, and on C# every module's functions are static members of one class. Link-name mangling for duplicates is still being fixed (round 5 item 13).
7. **Validate digits before `toI32`.** It diverges across targets: `"12a".toI32()` throws on C# and returns 12 on TS.
8. **One distinct `targetOptions.csharp.namespace` per Polyglot library,** and never import two generated namespaces into one C# file (CS0104).
9. **`Map` needs .NET 9** (`OrderedDictionary`). Spark targets net11, so this is fine. The test floor (net8) hits CS0234 for programs that use `Map`.
10. **A3, case-only renames:** until round 5 item 1 is fixed, a case-only rename of a source folder isn't detected for a route that leaves the config folder, which is exactly this layout. After such a rename, run the git hint by hand, or avoid the rename.
11. **Avoid temporaries numbered across the build on 0.10.2** (#76): a range ending on a call, or `!` on a call, could make a module come out differently depending on which input reached it. 0.10.3 numbers them per body. Spark is on 0.10.3, so the GS1 `.pg` follows no special rule for it.
12. **SDK 11.0.100-rc.2** injects dotnet-watch's browser JS module into Debug builds of Web-SDK libraries, and they fail with "scoped css bundles do not have matching endpoints". `Directory.Build.targets` turns `EnableHotReloadInRuntimeConfigDevFile` off for those libraries.
13. **Round-5 items fixed in #75:** link-name mangling (constraint 6) and the A3 case (constraint 10) were gating in round 5, so they are fixed in 0.10.2. The same goes for the "avoid until fixed" list in the language rules below. The rules stay as written, because the GS1 code was written against them.

**Language rules (as of `c436aae`) that the GS1 `.pg` code must respect:**
- **Null handling:**
  - a nullable value reaches a non-null slot only after narrowing or `!`;
  - **fields are not narrowed** (SPEC §4.3): read one into a local first;
  - `??` and `??=` need a target that can be null.
- **Declaration order:** an initializer may not use a declaration that comes later in the file, also when it reaches it through a call.
- **Records:**
  - a record's state is its positional fields, and its body holds only methods, operators and computed properties;
  - positional defaults are dropped by every emitter until round 5 item 11 is fixed, so don't use them yet.
- **Reserved names:**
  - identifiers containing `__` are reserved;
  - `_x` marks an unused local;
  - don't name a variable plain `_` until round 5 item 24 is fixed.
- **Function values:**
  - a named function used as a value must match its slot's function type exactly;
  - a method call on a function value is refused;
  - function types convert only when they're identical (no variance).
- **Avoid until fixed:** `abstract fn` (round 5 item 9), `x?.method()` and `?.` field reads (item 20), and statements before `super(…)` (item 8).

## 5. How the Spark session verifies a Polyglot drop

- **The Polyglot repo is read-only.** `C:\Repos\MintPlayer.Polyglot` is only read with `git show`, `diff`, `log`, `grep` and `archive`. Never checkout or fetch there, and never touch its working tree or build folders.
- **Build:** from a `git archive <sha>` into the session scratchpad, a Debug build of the solution plus `dotnet pack` of `MintPlayer.Polyglot.MSBuild`. Each drop gets a **unique prerelease version** `0.11.0-pr73.<sha7>`, because a reused version would be shadowed by the NuGet cache. Binaries are copied before they run.
- **Restores:** every restore that pulls the package uses a private `NUGET_PACKAGES`, with `-nodeReuse:false -p:UseSharedCompilation=false` and `MSBUILDDISABLENODEREUSE=1`.
- **Targets and floors:**
  - C# at the floor: net8.0, `LangVersion 11`, `Nullable enable`, `TreatWarningsAsErrors`, `CheckEolTargetFramework=false` (net9 for `Map` programs);
  - TS with **tsc 6.0.3** from Spark's `node_modules` (the global tsc is 5.8.3 and not used for gating), under `--strict` and the ng-spark library flags;
  - runs on Node, Python (`-I`) and PHP.
- **Who does what:** code reviews and hands-on agents work in parallel. Every new finding is also built with the previous head's CLI, to tell new bugs from old ones. The Spark session re-runs every gating finding itself before posting.
- **Triage** (tags used in the review comments):
  - **[R] regression:** right on the previous head (on all four targets) and wrong now. An **over-refusal** counts as a regression only when the refusal's stated reason is false. A deliberate, documented rule is not one: fields not being narrowed (SPEC §4.3) is a rule, and `f00dd24` only accepted that code because the conversion was unchecked.
  - **[H] hole:** a round's fix whose goal fails for a nearby variant.
  - **[O] older:** the defect predates #75.
  - **Silent** (exit 0, clean compile, wrong output) weighs more than **loud** (a compile error, refusal or crash). Python- or PHP-only behaviour older than #75 never gates.

## 6. The approval bar (as posted in round 5; used until approval)

Round 6 added two class-closing rules (follow every body kind; `this` in a subclassable constructor). From then on, a finding gated only if it was a regression, the current round's repro still failing, or a silent C#/TS miscompile. Everything else had to be fixed or documented without gating. A "regression" also required that the earlier head was right: a pass that came from a bug a later round removed doesn't count.

A new finding gates approval only if it is one of these:
- a regression against `c436aae`, or against behaviour verified in an earlier round;
- a hole in one of the fixes for the 24 round-5 items, found with those repros or nearby variants of them;
- a **silent** C# or TS miscompile of an ordinary shape: it builds, compiles cleanly at the floor and with tsc, then prints a wrong value or a value that differs between C# and TS.

A newly found compile error or refusal that isn't a regression doesn't gate; it must be fixed or documented. The next round's scope is these repros, the regression set and nearby variants of the fixes, with **no fresh language review**. The Polyglot session accepted both the bar and the scope ([6245957811](https://github.com/MintPlayer/MintPlayer.Polyglot/issues/73#issuecomment-6245957811)).

## 7. Channel protocol

- The owner made the #73 thread the channel between the two Claude sessions. Both post from the owner's account.
  - Spark comments start with **[Spark session]**.
  - Polyglot comments start with "Polyglot session → Spark session" and end with the Claude Code footer.
