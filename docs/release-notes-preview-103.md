# Spark 11.0.0-preview.103 / ng-spark 22.31.0 — installable apps and an external login that survives them

**Packages:** `MintPlayer.Spark`, `MintPlayer.Spark.Authorization`, `MintPlayer.Spark.IdentityProvider`,
`MintPlayer.Spark.Moderation`, `MintPlayer.Spark.Webhooks.GitHub`, `MintPlayer.Spark.AllFeatures` and
`MintPlayer.Spark.AllFeatures.SourceGenerators` → `11.0.0-preview.103`. npm: `@mintplayer/ng-spark` →
`22.31.0`, which now contains the auth library; `@mintplayer/ng-spark-auth` is **discontinued** (no new
versions; deprecated on npm). The majors do not move: the packages still target .NET 11 and Angular 22,
so every API break below ships as a minor/preview bump.

Spark apps can now be installed as PWAs (#464), and external login keeps working when they are (#490).
A provider popup that Android captures into the installed app hands its result back to the browser tab
over `BroadcastChannel`/`localStorage`, matched by a nonce. Inside the installed app, sign-in uses a
full-page redirect. External providers are `ISparkBuilder` presets that can be enabled from
configuration alone, X moves to OAuth 2.0, a Spark identity provider can be used as an upstream by the
stock OpenID Connect handler, and its login page offers the host's own external providers.

Decisions and evidence: [pwa_external_login_PRD.md](pwa_external_login_PRD.md). PWA set-up:
[guide-pwa.md](guide-pwa.md).

## ⚠️ Breaking changes

### 1. `@mintplayer/ng-spark-auth` is now `@mintplayer/ng-spark/auth/*`

The 15 entry points moved unchanged to nested entry points of `@mintplayer/ng-spark` (account,
auth-bar, confirm-email, core, forgot-password, guards, interceptors, login, models, pipes, register,
reset-password, routes, sign-in, two-factor). The root re-exports `provideSparkAuth`, `withSparkAuth`
and `sparkAuthClientMethods`. An app without auth still pulls no auth code.

1. Rewrite the imports:

   ```ts
   // before
   import { provideSparkAuth, withSparkAuth } from '@mintplayer/ng-spark-auth';
   import { SparkAuthService } from '@mintplayer/ng-spark-auth/core';
   // after
   import { provideSparkAuth, withSparkAuth } from '@mintplayer/ng-spark/auth';
   import { SparkAuthService } from '@mintplayer/ng-spark/auth/core';
   ```

2. In the SPA's `package.json`, remove `@mintplayer/ng-spark-auth` and depend on
   `"@mintplayer/ng-spark": "^22.31.0"`.
3. **Delete `src/spark-auth.setup.ts`** (gitignored, generated by `MintPlayer.Spark.Authorization` on
   build) and let the next `dotnet build` regenerate it. The build never overwrites an existing copy,
   so an old one keeps importing `@mintplayer/ng-spark-auth` and breaks the Angular build. If you
   customized it, rewrite its imports as in step 1 instead.

### 2. `configureProviders` is removed; the presets are `ISparkBuilder` extensions

`AddAuthentication<TUser>()` lost its `Action<IdentityBuilder>? configureProviders` parameter. The
`IdentityBuilder` presets (`AddGitHub`, `AddSparkGoogle`, `AddSparkMicrosoftAccount`,
`AddSparkFacebook`, `AddSparkTwitter`, `AddSparkLinkedIn`) are gone. Call the presets on the Spark
builder **after** `AddAuthentication` (each throws when it was not called first):

```csharp
// before
spark.AddAuthentication<SparkUser>(configureProviders: identity =>
{
    identity.AddGitHub(o => { o.ClientId = "…"; o.ClientSecret = "…"; });
    identity.AddSparkGoogle(o => { … });
});

// after
spark.AddAuthentication<SparkUser>();
spark.AddGitHub(o => { o.ClientId = "…"; o.ClientSecret = "…"; });
spark.AddGoogle(o => { … });
```

The presets are `AddGitHub`, `AddGoogle`, `AddMicrosoftAccount`, `AddFacebook`, `AddTwitter`,
`AddLinkedIn` (each also with a `(scheme, displayName, configure)` overload), `AddOpenIdConnect(scheme,
displayName, configure)`, `AddExternalProviders(configuration)` (see "Config-driven providers" below)
and `AddExternalScheme(scheme, policy)` for a handler you register yourself.

`SparkFullOptions.IdentityProviders` (`Action<IdentityBuilder>`) is now
`SparkFullOptions.ExternalProviders` (`Action<ISparkBuilder>`):

```csharp
options.ExternalProviders = spark => spark.AddExternalProviders(builder.Configuration);
```

### 3. Undeclared remote schemes and unknown provider keys throw at startup

- A remote authentication scheme (any `RemoteAuthenticationHandler<>`) registered without a Spark
  declaration now fails startup, naming the scheme. It used to fall back to "`email_verified=true` or
  no account". Use a preset, or declare it with `spark.AddExternalScheme("<scheme>", policy)` (an entry
  in `SparkAuthenticationOptions.ExternalProviders[scheme]` also counts).
- A key under `Spark:Auth:Providers` other than `GitHub`, `Google`, `MicrosoftAccount`, `Facebook`,
  `Twitter`, `LinkedIn` or `OpenIdConnect` throws in `AddExternalProviders`, naming the valid keys.

### 4. X (Twitter) uses OAuth 2.0 with PKCE

`AddTwitter` is the generic OAuth handler (no third-party package) against `x.com/i/oauth2/authorize`
and `api.x.com/2`, instead of OAuth 1.0a. On the X developer app:

- enable **OAuth 2.0** as a confidential (web) client and use its **Client ID / Client Secret**
  (`ClientId`/`ClientSecret`), not the 1.0a consumer key and secret
- register the callback `https://<host>/signin-twitter`
- turn on **"Request email from users"**; the email comes from `confirmed_email` (scope `users.email`)
  and is still treated as unverified (unconfirmed account plus a confirmation mail)

### 5. The popup hand-off is JSON with a nonce, and a closed popup is no longer an error

- The client sends `?popup=1&nonce=<n>`; the challenge endpoints answer 400 `invalid_nonce` to a
  malformed nonce (`^[A-Za-z0-9_-]{16,64}$`). The callback page posts
  `{ type: 'spark:external-login', success, error, nonce }` (System.Text.Json) instead of a JS literal,
  and also delivers it over `BroadcastChannel` and `localStorage`. Anyone parsing the old message must
  switch to this shape.
- `loginWithProvider()`/`linkProvider()` no longer resolve `popup_closed` when the popup looks closed
  (under COOP it can look closed long before the result arrives). The closed-poll only clears the new
  `SparkAuthService.externalLoginPending` signal. The promise settles when a result arrives, when a new
  external sign-in starts (the old one settles `popup_closed`), or after 10 minutes (`popup_closed`).
  **Take button and spinner state from `externalLoginPending`, not from the promise.**
- New error codes: `remote_failure` (the provider reported an error or correlation failed; a provider
  `access_denied` is still `no_login_info`) and `invalid_nonce`.

### 6. Identity provider token and endpoint changes

- `email_verified` in the id_token is a JSON boolean (it was the string `"true"`/`"false"`), as in
  userinfo.
- Roles in userinfo are claim `role` (was `roles`), as in the id_token.
- `/connect/login` (GET) is always mapped. With `LocalCredentials = Disabled` it shows only the
  external-provider buttons instead of answering 404; the POST and two-factor routes stay gated.
- The id_token has its own lifetime, `OidcApplication.IdTokenLifetimeMinutes` (optional, default 5).
  It used to reuse `AccessTokenLifetimeMinutes`.
- `/connect/logout` accepts `id_token_hint` and derives the client from it, so a relying party that
  sends only the hint (the stock OIDC handler) gets its `post_logout_redirect_uri` honoured. A hint
  that contradicts `client_id`, or carries a `scope`, is refused.
- The id_token adds `at_hash` and `auth_time`; userinfo and the id_token add `given_name`/`family_name`
  when the user has them stored. Discovery adds `response_modes_supported: ["query"]` and
  `claims_supported`.

### 7. SPARK030 checks for `@mintplayer/ng-spark`

`SparkAuthNpmPackage` now defaults to `@mintplayer/ng-spark`, so the SPARK030 warning ("package.json
does not declare …") fires until the SPA depends on it. If you set `SparkAuthNpmPackage` to
`@mintplayer/ng-spark-auth` yourself, remove the override.

## New

### PWA (#464)

- `@mintplayer/ng-spark/pwa`: `provideSparkServiceWorker()` registers Angular's service worker
  (production only, `registerWhenStable:30000`) with Spark's update policy: after `VERSION_READY` the
  next router navigation becomes a full page load, an unrecoverable state reloads at once, and updates
  are checked when stable, every 6 hours and when the tab becomes visible.
  `@angular/service-worker` is an optional peer, needed only by this entry point.
- [guide-pwa.md](guide-pwa.md): manifest, icons, `ngsw-config.json` with the navigation exclusions
  Spark needs (`/spark/**`, `/signin-*`, `/signout-*`, `/connect/**`, `/.well-known/**`), the kill
  switch, and why Spark never sends `Cross-Origin-Opener-Policy: same-origin`.
- `AddSpark()` adds a startup filter that serves `ngsw-worker.js`, `ngsw.json`, `safety-worker.js`,
  `worker-basic.min.js` and `manifest.webmanifest` with `Cache-Control: no-cache`. Nothing is needed in
  the app.
- All five apps (CodeCoverage, DemoApp, Fleet, HR, QnA) are installable; a Node guard test checks every
  `apps/**/ngsw-config.json` for the exclusions.

### PWA-safe external-login hand-off (#490)

- The callback page delivers the result over `postMessage`, `BroadcastChannel` and `localStorage`,
  acknowledges it, and closes itself, or shows "Signed in — you can close this window and return to
  your browser" with a Close button when the browser refuses. The client also re-reads on `visibilitychange`/`focus`, since the opener tab may be frozen.
- `provideSparkAuth({ externalLoginMode: 'auto' | 'popup' | 'redirect' })`, default `'auto'`: popup
  in a browser tab, full-page redirect when the app runs installed (`display-mode: standalone`).
- When `window.open` is refused, the sign-in page offers **Continue in this tab**, which retries the
  same provider by redirect.
- Redirect mode is first-class: `errorUrl` (option and challenge parameter) is where a failure lands
  with `?sparkExternalLogin=<code>`; the sign-in and account pages read, show and strip it.
- Every preset reports provider-side failures (`OnRemoteFailure`) back to the page instead of an
  exception page.
- Known limitation: Firefox on Android with the app installed shares nothing with the browser tab; the
  user gets the error and "Continue in this tab". Samsung Internet and Edge-installed apps likewise
  share nothing with a Chrome tab.

### Config-driven providers

```json
"Spark": { "Auth": { "Providers": {
  "GitHub": { "ClientId": "…", "ClientSecret": "…" },
  "OpenIdConnect": {
    "MintPlayer": { "DisplayName": "MintPlayer ID", "Authority": "https://id.example", "ClientId": "…", "ClientSecret": "…" }
  }
} } }
```

`spark.AddExternalProviders(builder.Configuration)` registers every provider with a section and a
non-empty `ClientId`; the capabilities endpoint, and so the client's `withExternalLogin()` buttons,
follow. Optional per-provider hooks run after binding, and a later individual preset call merges into
the configured one.

### OpenID Connect relying-party preset and IdP federation

- `spark.AddOpenIdConnect(scheme, displayName, configure)`: code flow with PKCE, query response mode,
  `email_verified` honoured by the verified-email policy. Client side: `oidcProvider(scheme,
  displayName, iconClass?)`. QnA signs in against HR as a worked example.
- A Spark identity provider's `/connect/login` lists the host's external schemes as buttons; they run
  in redirect mode and return to the pending `/connect/authorize` request, and a refusal code is shown
  on the login page.

### Sign-in and account pages show external-login errors

The shipped sign-in and account pages show the translated outcome of an external sign-in or link
(popup or redirect), and disable their provider buttons with a spinner while `externalLoginPending`
is set. A closed popup shows no error.

### The login page lists external providers

The password login page now shows the server's external providers above the form, separated by
"or", like the sign-in landing page. Both use the new `<spark-external-login-buttons>` component
(`@mintplayer/ng-spark/auth/external-login`), which an app can also host on a page of its own. With no
provider reported, the login page is unchanged. Concurrent `SparkAuthService.capabilities()` calls
share one request, and `takeExternalLoginResult()` answers each failure once.
`SparkProviderButtonContext` and `SparkExternalProviderView` moved to the new entry point and are
still re-exported from `@mintplayer/ng-spark/auth/sign-in`.
